# anti-slop audit 001 — FOQUS

Date: 2026-09-06
Guide: `github.com/miqdadbadjuber/anti-slop` (core `antislop.md`, skills `antislop-ui`,
`antislop-human`, `antislop-layoutmobile`, `antislop-copywriting`, `antislop-code`)
Mode: **2 (audit an already-finished project)**
Scope: the UI layer — `app/`, `components/`, `lib/i18n/id.ts`. The pure scheduling module
(`lib/scheduling/`) is out of scope; it renders nothing.

Priority follows the guide's own tiers: Hard Gate = **HIGH**, Purpose-Gate = **MEDIUM**,
Quality Locks and Craftsmanship = **LOW**.

Every contrast figure below was computed with the skill's `contrast-check.py`, never
estimated. The guide names eyeballing a grey pair "the most common accessibility
hallucination", so no pairing here is claimed to pass without a number beside it.

## HIGH — Hard Gate

### F-01 · `--fg-subtle` fails WCAG AA in both themes · R-25

The token that paints captions, task metadata, hints, the calendar's day totals and every
settings sub-label. It is used at `text-[11px]`, `text-[12px]` and `text-[13px]`, so the
4.5:1 normal-text bar applies, never the 3:1 large-text one.

| pairing | ratio | AA normal |
|---|---|---|
| dark `#6b7480` on `--bg` `#0b0d10` | 4.11 | FAIL |
| dark `#6b7480` on `--surface` `#14171c` | 3.79 | FAIL |
| dark `#6b7480` on `--surface-2` `#1c2027` | 3.45 | FAIL |
| dark `#6b7480` on `--surface-3` `#252a33` | 3.04 | FAIL |
| light `#858d99` on `--bg` `#f7f8fa` | 3.15 | FAIL |
| light `#858d99` on `--surface` `#ffffff` | 3.35 | FAIL |
| light `#858d99` on `--surface-2` `#f1f3f6` | 3.01 | FAIL |
| light `#858d99` on `--surface-3` `#e6e9ef` | 2.76 | FAIL |

Reach: 81 occurrences of `text-fg-subtle` across 31 files, so one token clears all of them.

A first pass at this fix only tested `--bg`, `--surface` and `--surface-2` and would
have shipped a token still failing on `--surface-3`, the deepest of the four. Every
surface a token can land on is part of the test, not just the common ones.

### F-02 · Em dashes in user-facing copy · R-02 (absolute)

Eleven in `lib/i18n/id.ts` (lines 64, 130, 135, 269, 304, 482, 494, 520, 521, 547, 558),
plus two places where `—` stands in for an empty value:
`components/settings/settings-screen.tsx:433`, `components/calendar/commute-field.tsx:94`.
Code comments are excluded: `antislop-code` is explicit that comments are not UI text.

### F-03 · One interaction exists only as a drag · R-32

Moving an agenda has a full keyboard path (`ScheduleSheet` in move mode). Creating an
"immediately after" link does not: `follows_agenda_id` can only be set by dragging one
block against another, so the feature does not exist without a pointer.

## MEDIUM — Purpose-Gate

### F-04 · `Sparkles` on the allocate button · R-04

`components/today/today-screen.tsx:290`, `components/planning/planning-wizard.tsx:190`.
The first glyph on the guide's generic-AI-icon list, on an action that means "put these
tasks on the calendar".

### F-05 · A literal 🍅 in the UI · R-04

`components/tasks/quick-capture.tsx:152`. The only emoji in the app. `antislop-ui` treats
emoji in UI text as the loudest shorthand for generated rather than written.

### F-06 · The ticker's countdown pulses forever · R-19

`components/shell/now-ticker.tsx:101` runs `animate-pulse` unconditionally.
`antislop-ui` calls perpetual motion with no user trigger noise; here the escalation is
already carried by colour (`soon` switches to `text-warning`).

### F-07 · The icon set has no written reason · R-04

Lucide supplies ~57 icons across 33 files. The guide does not ban it; it requires the
choice to be a decision with the reason recorded. Documentation only.

### F-08 · The palette exceeds R-29's 2–3 core plus accent, with the reason unrecorded · R-29, R-31

Ten semantic hues (`--p1..--p4`, `--prayer`, `--busy`, `--event`, `--overtime`,
`--buffer-switch`, `--buffer-commute`) on top of the neutrals and the accent. Each carries
information the scheduler acts on, which is a legitimate answer to the purpose test — but
the answer was never written down. Documentation only.

## LOW — Quality Locks and Craftsmanship

### F-09 · Every screen's `h1` repeats its own tab-bar label · C-3

"Tugas", "Kalender", "Hari Ini", "Pengaturan" render as an `h1` directly above a tab bar
that already says exactly that, on all four screens.

### F-10 · The task list has no search, and its search is already written · C-2

`TaskFilter.query` is implemented in `lib/todos/grouping.ts:30` and pinned to `""` at
`components/tasks/tasks-screen.tsx:80`. A finished feature with no way to reach it, and the
largest tap cost in a long list.

### F-11 · A confirm dialog and an undo toast for the same action

Three delete paths were examined and they turned out not to be the same case, so the
finding is recorded per site rather than as one sweep:

- **Agenda delete** (`agenda-sheet.tsx:270`): genuinely doubled. §4.3 requires the copy to
  say the todo survives, and `t.agenda.deleted` is `t.agenda.deleteConfirmBody` word for
  word, so the toast already carries the requirement. The dialog is a tap spent on a
  decision the toast reverses.
- **Event delete** (`event-sheet.tsx:266`): **left alone.** Its dialog body says something
  the toast does not, that deleting a recurring event removes every occurrence. That is a
  consequence a user cannot infer from a block on one day, so the confirmation is doing
  work.
- **Category delete** (`category-editor.tsx:77`): the opposite of the finding as first
  written. It had a confirmation and **no** undo, so the dialog was the only safety net.
  Replaced with the better trade: no dialog, and an undo toast that carries the same
  sentence about todos losing their category.

### F-12 · Missed review spends two rows per card on four labelled buttons

`components/tasks/missed-review.tsx:258-280`. The four icons are already distinct, and
`agenda-sheet.tsx:126-143` shows the icon-only idiom this codebase already uses.

### F-13 · The task detail sheet is ten flat groups with its best action last

`components/tasks/task-detail-sheet.tsx`. Notes, tags, place and dependencies are the rare
four; "Jadwalkan" sits below all of them. Priority chips print `"P1 · Mendesak"` where the
same widget in quick capture prints `P1`, forcing four wide chips across a narrow sheet.

### F-14 · Quick capture spends a row above the keyboard on fields nobody fills

`quick-capture.tsx:166-182` — a category `Select` and a `type="date"` input that duplicates
the "Hari ini" chip four lines above it. The estimate chip also cycles 1→8→1 with no way
back (`:149`).

### F-15 · Settings cannot be navigated

Ten sections, ~3841 px, no search and no disclosure. `components/settings/section.tsx:7`
has no collapsible mode, so five set-once sections sit above the three that get touched.

### F-16 · The calendar's view switch spends width on words

`calendar-screen.tsx:656` renders "Hari / 3 Hari / Daftar" as text on the row that also
carries the buffer legend and the 24-hour toggle. Day, three-day and list are all
shape-expressible; the grouping switch on Tasks is not, and stays text.

### F-17 · One hardcoded Indonesian string

`components/ui/toast.tsx:79` writes `"Urungkan"` inline while `t.common.undo`
(`lib/i18n/id.ts:29`) holds the identical value. The header of `id.ts` states the rule.

### F-18 · The tab-bar offset is a magic number in five places, at two values

`4.25rem` in `quick-capture.tsx:87`, `focus-pill.tsx:45`, `toast.tsx:131`; `3.25rem` in
`draft-bar.tsx:35`, `today-screen.tsx:283`, each re-adding `env(safe-area-inset-bottom)` by
hand. The disagreement is why the FAB and the draft bar can overlap.

### F-19 · Two identical "how many pomodoros" steppers

`components/tasks/completion-prompt.tsx:65-83` and
`components/tasks/missed-review.tsx:302-326` are the same `− N +` control in two files.

## Recorded, not fixed

### F-20 · Completing a task always costs a modal — a rule change

Completion is the most repeated action in the app and costs two taps: the checkbox, then
`Simpan` on a sheet that is already pre-filled. The component's own comment concedes "the
common case is one tap on Simpan". Making it one tap means committing the pre-filled count
straight from the checkbox with an undoable toast carrying a correction path.

This reverses part of **D-084**, which was requested deliberately, so it is listed and left
alone. It needs an explicit decision, not an audit.

### F-21 · `--busy` at 2.84:1 is a false positive

`--busy` fails 3:1 as a raw colour pair, but it is only ever a 20–25 % alpha background
band (`timeline.tsx:267`, `pick-timeline.tsx:375`) and never text, a border, or a component
boundary. The band's *label* carries its meaning, and that label's colour is covered by
F-01. No change; recorded so the next audit does not re-raise it.

### F-22 · No `DESIGN.md` · R-37

There is no design-direction file, and the product owner chose not to add one for this
pass. Per R-37 that is a FAIL, and it is reported as one rather than papered over: this
work is a **draft without direction**, dials **ENERGY 1 / RHYTHM 1 / MOTION 1**.

What the work was actually held to instead, since it is not nothing: the token layer in
`app/globals.css` and the reasoning in `DECISIONS.md` D-005 (dark-first semantic tokens),
D-006 (system font stack, no web font in a PWA that must open offline), D-098 and D-120
(compaction is layout, not touch targets), D-121 (the header loses its words, never its
information). That is a real system; it is simply not written as direction, and this audit
does not pretend otherwise.

### Click-through (R-35)

Driven in Chromium at 390x844, both themes. Console clean throughout, zero horizontal
overflow.

- capture: FAB, type, Enter creates a todo in one tap. Three created.
- quick capture: `Detail lainnya` starts closed, opens to reveal the category and date
  fields, and opens on its own when either already holds a value.
- estimate chip: two taps up reads 3, the minus reads 2. It was one-way before.
- search: the magnifier reveals the field, "paper" narrows the list to
  `["Baca paper difusi"]`, Escape clears the query and closes the field.
- detail sheet: field order is Judul, Kategori, Tenggat, Prioritas, Estimasi, **Agenda
  tugas ini**, Tambah subtask, then the fold. Jadwalkan is visible without scrolling.
- schedule: Jadwalkan offers 5 suggested slots, one tap places the agenda.
- agenda delete: no confirmation dialog, undo offered, undo restored the agenda.
- category delete: no dialog, undo offered; the list went
  `[Kerja, Riset, Personal, Ibadah]` to `[Riset, Personal, Ibadah]` and back on undo.
- calendar: the three-glyph view switch drives day, three-day and list; each carries its
  word in `aria-label` (Playwright resolved them by those names).
- settings: `JAM PRODUKTIF` starts closed, opens on tap, and is still open after a reload.
- keyboard: tab order follows visual order, focus outline computed at 2 px.
- agenda sheet: `Detail lainnya` starts closed on a plain agenda, Durasi and Jadwal are
  both visible without scrolling, and tapping it reveals the title override, the place and
  both buffer fields. Setting a title override and reopening the sheet finds the fold
  already open, so nothing the user set is hidden. Checked in both themes.
- both themes exercised on all four tabs.

Build clean; 340 Vitest tests pass **unchanged**, which is the evidence that none of this
touched a scheduling rule.

- R-18 fictional testimonials: **no**. None exist.
